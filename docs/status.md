# Статус проекта — WooCommerce SEO Optimizer

## 📌 Общее состояние
Проект в активной эксплуатации. Ключевые функции реализованы и протестированы на реальном магазине (категория логгеров данных, ~150 товаров). Код стабилен, ошибки обрабатываются, бекапы создаются, риски сведены к минимуму.

---

## 🧭 Проделанный путь

### Этап 1 — Базовая архитектура
- Трёхуровневая архитектура: Source → Normalization → Intelligence.
- Клиент для WooCommerce REST API: `getProducts`, `updateProduct`, `updateProductSlug`.
- Экспорт товаров в JSON (id, name, slug, meta_title, meta_description, focus_keyword, description, short_description, images).
- Импорт с валидацией Zod, сравнением изменений, diff и подтверждением.

### Этап 2 — Безопасность и надёжность
- Автоматические бекапы перед импортом.
- Команда `rollback` для восстановления.
- HTML‑валидация с подсветкой ошибок (баланс тегов, иерархия заголовков, `alt`, запрещённые теги).
- Поддержка Rank Math: поля `rank_math_title`, `rank_math_description`, `rank_math_focus_keyword`.

### Этап 3 — Интеграция с AI
- Проверены локальные модели (Ollama) — медленны и ненадёжны для HTML‑контента.
- Переход на OpenRouter для задач AI: SEO‑поля и контент генерируются облачными моделями (дёшево, быстро, стабильно).
- Пост‑обработка ответов: ограничение длины, удаление keyword stuffing.
- Поддержка few‑shot примеров (`--examples`).

### Этап 4 — Работа с Elementor
- На сайте используется Elementor; описание хранится в `_elementor_data`.
- Частичное обновление Elementor: заменяется только первый текстовый виджет (описание, преимущества). Технические таблицы (второй виджет) не трогаются — сознательное решение для сохранения точности.
- Флаг `--update-elementor` включает обновление Elementor‑контента.

### Этап 5 — Вспомогательные инструменты
- SEO‑анализатор без AI (оценка title, description, ключевых слов, `alt`, заголовков).
- Лимитер токенов OpenRouter (10 000 токенов за 10 минут).

## ✅ Что работает сейчас
- Экспорт (фильтрация по ID, категории, `catId`).
- Импорт (включая обновление slug и Elementor при флаге).
- AI‑улучшение (SEO + контент) через OpenRouter.
- HTML‑валидация (цветные ошибки, фрагмент кода).
- Бекапы и `rollback`.
- SEO‑анализатор.
- Поддержка Rank Math и базовых полей WooCommerce.

---

## 🟢 Сильные стороны
- Безопасность: бекапы, `rollback`, валидация HTML, подтверждение перед импортом.
- Точность данных: технические таблицы Elementor не изменяются AI.
- Гибкость: легко добавлять поля, менять промпты, подключать другие API.
- Human‑in‑the‑Loop: контроль на каждом шаге.
- Минимальные расходы: OpenRouter ≲ $0.50 за 150 товаров.

---

## 🟡 Недостатки и ограничения

### Текущие ограничения
- Экспорт ограничен 50 товарами за раз (нет автоматической пагинации — можно расширить).
- Elementor обновляет только первый текстовый виджет — при сложной структуре (колонки, вкладки) возможны нарушения.
- Нет веб‑интерфейса (только CLI).
- Нет автоматического перезапуска после ошибок (есть логи и бекапы).

### Риски
- OpenRouter может изменить бесплатные модели — следить за балансом.
- Элементы Elementor, отличные от `text-editor`, не обновляются (намеренно; при необходимости можно добавить другие типы).

1. Пагинация — автоматически загружать все товары (цикл по страницам WooCommerce API).  
2. Веб‑интерфейс (React) — визуальный diff и редактирование.  
3. Поддержка других конструкторов страниц (WPBakery, Gutenberg).  
4. Интеграция с Google Search Console — подтягивать реальные запросы для товаров.  
5. A/B‑тестирование мета‑тегов.  
6. Пакетная обработка нескольких JSON‑файлов (импорт всей папки).  
7. Локальные LLM через Ollama — при появлении быстрых и корректных моделей.
